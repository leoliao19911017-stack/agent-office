一、改了什么

两个决策端点原先的形态是「进门读档案 → 校验（锁外）→ 拿写锁 → 用进门时读的旧档案写回」。校验与写入之间存在 check-then-act（TOCTOU）形态的缺口。本轮重构为：

lockDecision(taskId/stepKey)          ← 先拿写锁
  ├─ 锁内重读任务档案（不是请求进门的旧快照）
  ├─ 锁内全量重校验：
  │    computeDecisions        前置条件（awaiting 且前序全 done 才 actionable）
  │    artifactGateOf          类型门禁（plan 步骤 expectsKinds:['plan']）
  │    artifactVersionGateOf   版本门禁（statSync 字节数 + sha256 物理实测 vs 登记）
  ├─ 锁内原子写（saveTaskFileAtomic：随机 tmp + renameSync 顶替）
  └─ finally unlockDecision

opId 幂等重放检查保留在锁外、写之前（重放是读缓存，不需要互斥）。

诚实定性（必读）：修复前，两个端点从校验到写回全程同步、中间无 await，Node 单线程事件循环下进程内不存在可利用的穿插窗口——外部可观察的行为契约（409 拒绝、不重复写入、失败零成功记录）在本轮改动前后是一致的、且早已正确。因此本轮性质是结构性加固：把「恰好正确」的隐式不变量变成显式临界区，防止未来任何人在校验与写入之间插入 await（例如加个日志上报、缓存查询）时无声引入真 TOCTOU。同时把「写回必须基于锁内重读的档案」变成代码结构本身，不再依赖读者自觉。
