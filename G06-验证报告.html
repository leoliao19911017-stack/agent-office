一、改了什么（3 个文件 + 1 个新脚本）

1. web/shared.js — api()

  • 新增第三参 timeoutMs（默认仍 12000）：首轮初始化由调用方传 8000。
  • 修掉伪造成功源头：之前 2xx + 无效 JSON 会 return null，上层把 null 当成功灌进 lastState/hermesData。现在抛错并标 err.isDataError = true，与 isHttpError / 超时 / 网络错误四类可区分。

2. web/app.js — 四态 + 退避链

  • 新增状态 initPhase（loading→connected / conn-fail / data-fail）、phaseReason、firstRound、failStreak、polling，及 errShort() 归类（TimeoutError→请求超时；TypeError→网络错误；isDataError/isHttpError→原文）。
  • tick()：首轮 6 个请求全部 8000ms 超时；allSettled 后判四态——health 被拒=连接失败；health 通但 state/flow 任一被拒=数据获取失败；都成功=已连接。失败轮 console.error('[G06] …') 含模块明细；恢复时 console.info 报「已重新连接，恢复真实数据」。
  • 轮询从固定 setInterval(3000) 改为自调度退避链：2s→4s→8s→之后最多每 30s；任一轮成功清零回 3s。sp-poll-btn 判断同步改 polling（保留用户手动暂停语义）。
  • 渲染层同口径四态：底栏 #sb-conn（wait/ok/off + tooltip 带重试策略）、设置弹层 #sp-conn、顶栏 #tb-task、中央空态文案带原因。
  • 启动看门狗：首轮已有失败结论则不重复挂 bootFail，只兜「悬死无结论」。

3. web/app.css — 底栏规格色

  • #statusbar 补 line-height: 18px。
