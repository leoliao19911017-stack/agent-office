  • 终态 interrupted，不是 completed；助手消息 interrupted（空内容不冒充回复）
  • 引擎清掉坏 session 引用（→ null），并追加 system 消息说明下一句会新开 会话、旧上下文不带过去
  • 说明：任务书原文写「状态是 failed」。本实现状态词汇表（chat-state.mjs 十态）没有裸 'failed'——有明确证据的失败落 interrupted + error.kind。判据核心（不冒充 completed、失败原因如实可见）满足。
过程中发现并修复的问题
  • 首请求轮次被启动对账误伤：引擎懒初始化时 reconcileOnStartup 把刚入库的 queued 轮次当成「重启残留」落成 interrupted。修复：POST 处理器先取引擎（对账先跑）再建轮次（web/api-chat.mjs 已带注释）。修复后复测通过。
  • 调用方编码坑（非产品缺陷）：curl 命令行内联中文经 GBK 转码后成乱码，claude 如实回复「收到乱码」（thread th-ea421adfb5 留档）。改 UTF-8 文件体后全链路正常；前端 fetch 接入无此问题。
