## 三、这一路踩的 7 个坑（全部真实）

### 坑 1：open_id 是应用级隔离的

- Hermes 应用下：`ou_2948072d13067cf165b27500f3fa8c40`
- Ann 应用下：`ou_a67039a38ab9e4f417f98605a4394b43`

用错就报 `99992361`。**这是飞书的设计：同一个用户在不同应用里 open_id 不同。**

**怎么拿**：让用户给 bot 发消息，从 `im.message.receive_v1` 事件里读 `sender_id`。

### 坑 2：创建应用时选错企业

第一次建的 Alice（`cli_aa7f628a62f8dd08`）不在 Leo 常用租户里，bot 搜不到也发不了消息。

### 坑 3：`lark-cli` 版本不支持 `--content -`

- 报错：`--content is not valid JSON: -`
- 根因：`AppData\Roaming\npm` 下那份是 1.0.96，不支持从 stdin 读 JSON
- 修复：升级到 1.0.100

### 坑 4：`.cmd` 包装器必须是 `%~dp0` 相对路径

Autoloop 的 `commandLine()` 正则：
```js
/"%(?:dp0%|~dp0)\\]?([^"\r\n]+\.(?:[cm]?js|exe))"\s+%*/
```

只认这种格式。写成绝对路径 `"C:\...\xxx.js"` 会报「不能直接运行」。

### 坑 5：`options.lark` 只能是单个程序名

`commandLine([program, ...args])` —— `program` 不能是带空格的命令串。
`"C:/Tools/node24/node.exe C:/path/x.mjs"` 会报 `spawn ENOENT`。

### 坑 6：`access` 不是规则级字段

- ❌ `rule.access = "read"` → 报「不认识的字段 access」
- ❌ `rule.to = {id: "claude", access: "read"}` → 报「to 不是已登记的 Agent」
- ✅ 在 `agents` 里定义新 Agent：`agents["claude-readonly"] = {use: "claude", access: "read"}`，规则写 `"to": "claude-readonly"`

### 坑 7：改规则后必须重启中台

`service install` 才会重新读 `rules.json`。改了不重启，中台还用旧规则派活。

**这个坑是 Claude Code 自己指出来的**——它说「配置已修」和实际启动参数对不上，我们才去查。
