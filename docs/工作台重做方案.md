# Agent Office 重做方案：给 AI 小白用的工作台

问题定义时间：2026-11-18
现状：GPT 给 8.0 分，但 Leo 说「完全没法用」「界面看不懂」「AI 小白没法用」

---

## 一、先承认问题：8.0 分是评错了

**GPT 的 8 个维度里，没有一个在问「小白能不能用」。**

它评的是：信息架构 7.7、视觉完成度 7.6、功能完整性 8.2、数据真实性 8.2、交互流畅度 8.1、错误处理 8.3、可维护性 8.7、细节打磨 7.4。

**这 8 个维度全是「专业评审视角」，没有一条是「第一次用的人能不能看懂」。**

**所以 8.0 分是真的，但评错了对象。它评的是一个数据看板做得好不好，不是评这个工作台能不能用。**

这是我的责任：评分标准是我定的，我没把「小白可用」写成硬门槛。

---

## 二、Leo 要的真实流程（原话拆解）

```
① 我给一个评审标准分（比如 8 分）
② 我给需求
③ 看到「我和 GPT/Codex 沟通确认」的过程，产出需求文档
④ 我下发开发任务单给 Claude
⑤ Claude 输出：开发计划 + 测试用例 + 测试方案
⑥ 交给我和 GPT 评审
⑦ 不达标 → 反馈优化方案给 Claude → 回到 ⑤
⑧ 循环直到达标
```

**这不是七步流水线，这是一个「有起点、有终点、会自动循环」的闭环。**

**现在界面上那条 `01 原始需求 → 02 需求文档 → 03 开发计划 → ... → 07 最终交付` 完全对不上：**
- 没有「目标分」这个概念
- 没有「讨论确认」这个环节的可见性
- 循环是隐形的（GPT 评完不合格又回去改，用户看不到）
- 用户不知道现在该干什么

---

## 三、借鉴 Orca 的什么（技术底座）

Orca 的核心模型（调研文档已确认）：

```
Run      = 持久命名空间 + 收件箱
Task     = 工作项，带 spec、依赖、状态
Dispatch = 一次执行尝试，「完成」的权威来源
Message  = worker_done / heartbeat / escalation / question
Gate     = 决策关卡，阻塞直到有人回答
```

**我们该吸收的三条，不是全部：**

### ① 每个 Agent 必须主动报到（worker_done 契约）

已有雏形（done.json），但要扩展成**人能看懂的形式**：
- 不是给程序看的 JSON，而是给用户看的一句话：「我改完了 3 项，2 项没问题，1 项卡在找不到接口」

### ② 长任务要发心跳（heartbeat）

**用户最焦虑的是「它到底在不在动」。**
现在页面上只有「执行中」三个字，跑 40 分钟用户就慌了。

**改成：**「Claude 正在改第 3/7 项，已用 12 分钟，上次心跳 30 秒前」

### ③ 卡住要「问」，不能自己闷着

**Orca 的 `ask`：带选项、带超时、阻塞等待回答。**

**这是小白工作台最需要的东西**：Agent 遇到拿不准的事，不是自己瞎猜或死等，而是弹一个问题给用户选。

## 四、界面该怎么改：从「数据看板」改成「任务驾驶舱」

### 核心思路：一屏只回答一个问题

**小白打开页面，脑子里只有一个问题：「我现在要干什么？」**

**现在的页面同时显示 7 步流水线 + 需求列表 + 审批详情 + Agent 状态 + 文件指纹，信息密度太高了。**

### 新布局（一屏一件事）

```
┌─────────────────────────────────────────────┐
│  顶部：当前任务名 + 目标分 8.0 + 当前 6.7      │
├─────────────────────────────────────────────┤
│                                             │
│   中间：一句话说清「现在在干什么」            │
│                                             │
│   「Claude 正在改第 3 项：审批详情滚动」      │
│   ▓▓▓▓▓▓░░░░░░░░░  43%  已用 12 分钟        │
│                                             │
│   ── 前面发生了什么（可折叠）──              │
│   ✓ 需求已确认                                │
│   ✓ 需求文档已生成（3 轮讨论）                │
│   ✓ 开发计划已确认                            │
│   ▸ 正在开发                                  │
│   ○ 评审                                      │
│                                             │
├─────────────────────────────────────────────┤
│  底部：唯一一个按钮                          │
│  ┌────────────────────────────────────┐    │
│  │  我确认 / 我要改 / 先停下           │    │
│  └────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

**关键变化：**

| 现在 | 改成 |
|---|---|
| 7 个步骤平铺，全靠自己理解 | 只显示「当前 + 前面折叠 + 后面灰着」 |
| 一堆专业术语（需求/任务书/产物/交付物） | 全改成人话 |
| 多个按钮（通过/打回/重试/决策） | 同一时刻只有一个主按钮 |
| Agent 状态一堆数字 | 一句话：「Claude 正在干活，30 秒前有动静」 |

### 五个页签改成三个

```
现在：工作台 / Agents / 技能 / 文件
改成：我的任务 / 干活记录 / 设置
```

- **我的任务** —— 上面那个驾驶舱
- **干活记录** —— 每个 Agent 干了什么、现在在干嘛（人话版日志）
- **设置** —— 目标分、Agent 配置、技能管理

**「文件库」「技能中心」这种专业功能，藏进设置里，不放在一级导航。**

## 六、循环怎么让用户看见

**现在的循环是隐形的，用户只看到分数不动。**

**改成显式循环条：**

```
第 1 轮  6.6  ─┐
第 2 轮  6.7  ─┤  已 3 轮，还差 1.3 分
第 3 轮  8.0  ─┘  ✓ 达标

每轮点开能看到：改了哪几项、GPT 说了什么、分数为什么变
```

**用户要能回答：「为什么又改一轮？这次改跟上次有什么区别？」**

---

## 七、目标分怎么成为一等公民

**现在「目标 8 分」只写在脚本里（`TARGET=8.0`），界面上完全看不见。**

**改成：**
- 创建任务时让用户填目标分
- 顶部常驻显示「目标 8.0 · 当前 6.7 · 还差 1.3」
- 达标时全屏提示「达标了，8.0 分」，并且停止循环
- 用户可以随时改目标分

---

## 八、我建议的实施顺序

**第一步（最急）：重做首页**
把驾驶舱做出来，一屏一件事，人话术语。**其他页面先不动。**

**第二步：循环可视化**
把「第几轮、每轮改了啥、GPT 说什么、分数怎么变」做成可折叠的时间线。

**第三步：把不确定性摆到台面上**
Agent 卡住时弹问题给用户选（借鉴 Orca 的 `ask`）。

**第四步：收掉专业页面**
文件库、技能、Agent 原始状态挪进设置。

## 九、需要 Leo 拍板的三件事

**一、目标分填在哪**
- A. 创建任务时填（每个任务独立目标）
- B. 全局设一个默认目标，任务可以覆盖

**二、一个任务的完整流程要不要强制走完**
- A. 强制：必须确认需求才能开发
- B. 可以跳步：老手直接派活

**三、评审完不达标时，默认动作**
- A. 自动继续改（不用问）
- B. 每次问用户「继续改还是停下」

**我的建议：一选 A，二选 B（默认强制但可跳过），三选 A（自动继续，但异常才问）。**
